# JURY Analytics — инструкции для продолжения работы

- Начни с [ROADMAP.md](ROADMAP.md), единственного актуального плана приёмки, затем [PROGRESS.md](PROGRESS.md) и [RUNBOOK.md](RUNBOOK.md). Исторические документы не являются актуальным статусом.
- Репозиторий DrKarpov/jury-analytics: main — код, data — неизменяемые исходные факты и чекпойнты. Pepegun Analytics — только образец, не изменять.
- Перед изменениями получи фактические SHA обеих веток, последние Actions и соответствующие статус-файлы data. Не копируй цифры из чата без проверки.
- Продолжай первый незакрытый этап. Не переписывай продукт с нуля, не сокращай требования, не превращай каждый пример ошибки в индивидуальный хардкод. Исследуй весь класс проблемы, затем массовая проверка и регрессия.
- Данные TON: точные целые nano-units, хеши транзакций/сообщений, LT, статус, первичные payload и связь с ledger. Не путай transfer rows, трассы, сделки, адреса и пользователей; не принимай совпадение двух индексаторов за доказательство полной истории.
- Не раскрывай ключи, не извлекай ключ Wallet Agent, не делай платные обязательные зависимости. Wallet Agent пригоден для независимой ручной проверки, не для runtime публичного сайта.
- Не переписывай исторические данные; изменения интерпретации только с доказательствами и воспроизводимой lineage. Не выключай тесты ради зелёного CI.
- Каждый рабочий проход: реальные измерения до/после, исправление причины, тесты с положительными и отрицательными случаями, проверка фактических результатов Actions и публикации. Задачи backfill ограничены по времени и сохраняют завершённые стадии.
- Обновляй PROGRESS.md при достижении измеримой точки или смене блокера. Указывай точный cutoff, ref, числитель и знаменатель, область измерения, остаток и ссылку на доказательство. Не выдавай начатую проверку за успешную.
- Пользователь хочет готовый продукт, не архив и не новый проект. Если сессия оборвалась, продолжи здесь по ROADMAP.md и реальному состоянию GitHub.
